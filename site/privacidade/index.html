Política de Privacidade do Trail

Atualizada em 21 de outubro de 2026 · Versão 1.0.0

Resumo

O Trail é uma extensão de navegador para perícia de alterações e automações em registros do ServiceNow. A extensão processa dados e conteúdos do ServiceNow no próprio navegador do usuário, opera exclusivamente por requisições de leitura (GET) e não envia dados a servidores próprios nem a terceiros (sem telemetria e sem servidores intermediários).

Dados tratados e conteúdo do ServiceNow

Ao navegar em formulários ou listas e ao iniciar uma investigação, o Trail consulta a instância ServiceNow da aba ativa utilizando a sessão autenticada do usuário (via chamadas HTTP GET à API de tabelas):

  • Registros, auditoria e histórico de alterações: lê o registro aberto, entradas de auditoria (sys_audit), registros de transações (syslog_transaction), eventos de sistema (sysevent), execuções de flows (sys_flow_context) e automações associadas. Esses registros podem incluir identificadores de usuários e dados pessoais cadastrados no ServiceNow, tais como nomes de usuários, autores de alterações, solicitantes, analistas responsáveis e notas de trabalho (work notes ou comentários do chamado).
  • Contexto de formulário e interface: inspeciona rótulos e opções dos campos (metadados da tabela em /api/now/ui/meta), valores de campos e metadados de tabelas na página ativa para correlacionar os campos exibidos com o histórico auditado.
  • Processamento local: a correlação pericial, o cálculo de pontuação de candidatos e a reconstrução da linha do tempo são executados no motor da extensão localmente no navegador.

Armazenamento e ciclo de vida dos dados (Retenção)

Os dados processados pelo Trail são gerenciados localmente nos seguintes mecanismos do navegador:

  • Sessão da extensão (chrome.storage.session): armazena o estado pericial associado a cada aba (chave tab:tabId), incluindo o resultado da última investigação, investigações em lote, relatório de acessibilidade de fontes e metadados temporários da tabela. Esse estado permanece disponível enquanto a aba do registro estiver aberta — permitindo fechar e reabrir o painel sem perder a análise em andamento —, é limpo ou atualizado quando a página é recarregada ou quando o usuário troca de registro, e é removido quando a respectiva aba é fechada no navegador (chrome.tabs.onRemoved). Toda a área de sessão é descartada ao encerrar o navegador.
  • Token da sessão: para consultar a instância em nome do usuário, o token de sessão do ServiceNow da página (g_ck) fica guardado em chrome.storage.session, por instância, somente em memória e só enquanto o navegador estiver aberto. Ele nunca é enviado a outro lugar além dessa mesma instância.
  • Armazenamento local da extensão (chrome.storage.local): armazena o estado de interface do painel flutuante (aberto, fechado ou minimizado), a posição proporcional customizada da bolinha-assistente na tela e o controle de exibição inicial do balão de boas-vindas.
  • Sincronização de preferências (chrome.storage.sync): armazena as preferências de configuração do usuário (tema visual claro, escuro ou sistema, idioma da extensão, atalho de teclado configurado, preferência entre painel lateral ou janela, exibição de ícones) e a lista de domínios de instâncias que o usuário conectou.

Nenhum conteúdo de registros, credenciais ou dados periciais são compartilhados com terceiros ou transmitidos para servidores fora da instância ServiceNow conectada pelo usuário.

Permissões e controle de acesso (ACLs)

  • Somente leitura (GET): a extensão emite unicamente requisições de consulta; o código não contém rotas ou instruções para criar, alterar ou apagar registros na instância.
  • Operação sob as permissões da sessão do usuário: o Trail realiza consultas autenticadas através da sessão do usuário no navegador e recebe apenas o conteúdo que as listas de controle de acesso (ACLs) e regras de segurança do servidor ServiceNow autorizam para aquele perfil. Ele não ignora nem contorna as restrições de segurança do servidor.
  • Permissões sob demanda: o acesso à instância é concedido apenas quando o usuário decide conectar o Trail naquela origem específica e pode ser revogado a qualquer momento nas configurações de extensões do navegador.

Contato

Dúvidas sobre o funcionamento técnico ou sobre esta política podem ser encaminhadas pela página da extensão nas lojas de aplicativos do navegador ou pelo repositório do projeto.

Privacy Policy (English)

Summary: Trail is a browser extension for ServiceNow record and change forensics. The extension processes ServiceNow data and content locally inside the user's browser, operates strictly via read-only (GET) requests, and does not transmit data to proprietary or third-party servers (zero telemetry and no intermediary backend).

Data handling and ServiceNow content

When you view records or trigger an investigation, Trail queries the active tab's ServiceNow instance using your existing authenticated browser session (via HTTP GET requests to the Table API):

  • Records, audit logs, and change history: reads the target record, field audit entries (sys_audit), transaction logs (syslog_transaction), system events (sysevent), flow executions (sys_flow_context), and configured business rules. Depending on the ticket or table inspected, this data may contain user identifiers and personal information stored in ServiceNow, such as user names, change authors, callers, assigned technicians, and ticket work notes or comments.
  • Form and UI context: inspects field labels and choices (table metadata from /api/now/ui/meta), field values, and table metadata on the active page to correlate UI fields with audit history.
  • Local processing: all forensic correlation, candidate scoring, and timeline reconstruction are performed by the extension engine locally within your browser.

Data storage and lifecycle (Retention)

Data handled by Trail is retained strictly locally within browser storage mechanisms:

  • Extension session storage (chrome.storage.session): stores per-tab forensic state (keyed by tab:tabId), including the latest field inspection result, batch runs, source access reports, and temporary table metadata. This state remains available while the corresponding tab remains open — allowing users to close and reopen the panel without losing in-flight analysis —, is refreshed or reset when the page reloads or when navigating to another record, and is deleted when the tab is closed (chrome.tabs.onRemoved). All session storage is cleared when the browser is closed.
  • Session token: to query the instance on the user's behalf, the ServiceNow session token of the page (g_ck) is kept in chrome.storage.session, per instance, only in memory and only while the browser is open. It is never sent anywhere other than that same instance.
  • Extension local storage (chrome.storage.local): stores floating panel UI state (open, closed, minimized), the assistant bubble's custom proportional screen coordinates, and first-time welcome tip flags.
  • Preferences storage (chrome.storage.sync): stores user settings (light/dark/system theme, extension language, custom keyboard shortcuts, side panel vs. detached window preference, field icon visibility) and the list of user-connected ServiceNow instance domains.

No record content, credentials, or forensic data are shared with third parties or transmitted to servers outside the user-connected ServiceNow instance.

Permissions and access control (ACLs)

  • Read-only (GET requests only): the extension exclusively issues query requests; it contains no code paths to insert, update, or delete records or configurations on the instance.
  • Server ACL compliance: Trail queries ServiceNow through the user's authenticated session and can only access data permitted by the instance's Access Control Lists (ACLs) and security rules for that account. It does not bypass server-side security policies.
  • On-demand permissions: host access is requested on demand only when you choose to connect a specific instance domain and can be revoked at any time via browser extension settings.
